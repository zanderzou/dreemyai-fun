Record where the sign-in attempt stopped before clearing browser data or trying a different account. A page that never loads, a sign-in provider that fails to return you and an account that opens empty are different support requests.

Dreemy's public contact page lists login problems under technical support and asks for the linked email, the device or browser and the relevant error. Put those details into one short note after reproducing the problem once. A support note does not need your password or the text of the conversation you were trying to open.

## Write the point where the screen changed

For example: “16 November, 14:20 Gulf Standard Time. Desktop browser. I opened the sign-in page, followed my usual sign-in route and returned to the site. The same sign-in prompt was still on screen. I did not reach my profile.” This is an example, not a documented Dreemy error message.

If the error appeared before you left the site, say so. If you reached a profile but found unfamiliar details, use the account mismatch as the subject. An exact error phrase is often more useful than an uncropped screenshot of the whole tab.

## Send only the details that help locate the attempt

Make a copy of a screenshot before cropping it. Keep the error text visible. Remove conversation previews, inbox messages, one-time codes and any URL query that might carry a sign-in token. Attach the sanitized copy through the official support route. The linked account email can help support locate the case, but keep secret credentials inside your sign-in flow.

Once you send the note, keep its date and reply reference. Log a new browser or signing method as a separate attempt. You will be able to tell support what changed without asking them to reconstruct multiple login paths from one screenshot.
